01

Purpose & Technical Architecture

Node.js · Fastify · Socket.IO · Upstash Redis · Cloudflare R2
Core Business Purpose of Module I:
CreatorConnect Messaging is not a generic chat system; it is a transaction-anchored collaboration hub designed to facilitate verified hiring between Creators, Brands, Production Professionals, and Podcasters. Every conversation can be contextually tethered to an active Assignment Brief (SOW §11), an application status (SOW §12), or a mutual connection request.

Critical Business Rules & Anti-Bypass Controls:
  • Anti-Bypass Protection (Admin Spec §519): Phone numbers, email addresses, and external payment handles (UPI / PayPal) detected in the first 3 messages of a newly established conversation trigger soft user warning prompts and are queued for admin moderation.
  • Daily Outreach Quota (SOW §17): Free tier accounts are throttled to a predefined number of new direct message outreaches per day, gating unlimited messaging behind the Creator Pro subscription tier.
  • Cloudflare R2 Direct Pre-Signed Uploads: Images, PDFs, and voice clips are uploaded directly to Cloudflare R2 via pre-signed backend URLs, preventing high-bandwidth media from loading the Node.js/Fastify server.
  • Presence & Real-time Socket Scaling: Upstash Redis stores active socket room joins, typing status TTLs (2.5 seconds), and user online presence heartbeats.

UI Data Payloads & Backend State Contracts

What Data Must the Messaging UI Carry?

1. Summary of Data Required by the UI

To power real-time messaging, optimistic updates, Cloudflare R2 media streaming, anti-bypass guards, and assignment anchors, the client-side UI (Flutter / Riverpod) must carry three distinct tiers of data:

Data Domain Specific Attributes Carried by UI Storage Layer Real-Time Protocol
Conversation Metadata Conversation UUID, participant profiles (name, avatar, verification status, role), unread count, pinned status, muted status, linked assignment summary (brief ID, title, budget, escrow status). Supabase PostgreSQL + Upstash Redis Cache REST initial fetch + Socket.IO updates
Message Entities Message UUID, client-side temporary UUID (for optimistic local bubble), sender UUID, recipient UUID, content text, message type (TEXT, IMAGE, PDF, AUDIO, MILESTONE_CARD), timestamps (sent, delivered, read), status ticks. PostgreSQL messages table Socket.IO message:send, message:new, message:ack
Cloudflare R2 Media Metadata Storage object key, public Cloudflare CDN URL, pre-signed upload URL, MIME type, file size in bytes, image width/height, voice note duration in seconds. Cloudflare R2 Object Store + PostgreSQL attachments HTTP PUT direct to R2 + metadata payload via Socket.IO
Real-Time Transient Presence Online presence boolean, last seen timestamp, active room socket ID, peer typing indicator boolean (2.5s auto-expire TTL). Upstash Redis In-Memory KV Socket.IO presence:update, typing:status
Safety & Compliance Flags Anti-bypass flag boolean (phone/email/UPI detection in first 3 messages), report status, block status, user daily connection quota remaining. PostgreSQL user_blocks, chat_flags Client-side Regex check + Backend validation hook
