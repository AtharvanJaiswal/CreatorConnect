## 1. Executive Summary & Verification Methodology

Every active administrative frontend route in `apps/web-shell` was audited directly against the Fastify backend implementation in `apps/api/src/modules/*` and database models in `packages/database`. The audit evaluated 10 strict criteria per screen:

1. **HTTP Method**: Exact method conformity (`GET`, `POST`, `DELETE`, etc.).
2. **Endpoint Path**: Parameterized path and prefix `/api/v1/*`.
3. **Request Query/Params**: TypeBox schema constraints and pagination limits.
4. **Request Body**: Required fields, minLength, and format validations.
5. **Response Contract**: TypeBox response schema structure and DTO mapping.
6. **Authorization Permission**: Pre-handler `fastify.requireAdminPermission(...)` and CASL mapping.
7. **Pagination**: Keyset cursor or offset pagination correctness.
8. **Error Handling**: Graceful degradation on 400, 401, 403, 404, 500 without crashing.
9. **Loading State**: Presence of explicit spinners or skeletons during async fetch.
10. **Data Source Truth**: Complete absence of fabricated mock records or silent mock fallbacks.

### Standard Classification Definitions

- **VERIFIED**: The backend implementation and frontend integration are fully connected and all 10 criteria pass.
- **PARTIALLY VERIFIED**: The backend implementation exists and is functional, but the frontend views it with partial aggregation or per-entity constraints.
- **FRONTEND ONLY**: The frontend view exists without a corresponding authoritative backend operation.
- **BACKEND ONLY**: An API endpoint is registered in Fastify but has no frontend UI component consuming it.
- **BLOCKED**: Implementation is gated on pending legal, financial, or governance approval.
