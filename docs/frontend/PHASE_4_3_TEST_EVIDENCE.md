## 3. Focused Security & Concurrency Proofs Verified

- **Authorization Closure & Role Revocation:** Verified across `admin-authorization-closure.spec.ts`, `community.spec.ts`, `support.spec.ts`, `users.spec.ts`, `lifecycle.routes.spec.ts` (`401`/`403` fail-closed negative cases, cross-user legal-hold `DELETE` IDOR `404`, support ticket internal note isolation, immediate `403` after role revocation, `403 STAGE_A_GOVERNANCE_BLOCKED` on erasure execute).
- **Financial Concurrency & Idempotency:** `admin-finance-concurrency.spec.ts` verified via real concurrent HTTP requests (`Promise.all`) against PostgreSQL `FOR UPDATE` locks:
  1. Two distinct Finance Admins clicking `/approve` concurrently -> strictly `1x 200`, `1x 409 Conflict`, `1` ledger tx, `1` outbox event.
  2. Simultaneous `/approve` vs `/reject` -> strictly `1x 200`, `1x 409`, coherent approval & refund state.
  3. Simultaneous partial refunds exceeding remaining balance -> `1x 201`, `1x 400`, zero overdraft.
  4. Concurrent duplicate `Idempotency-Key` -> single refund created (`id` identical); same key + different payload -> `409 IDEMPOTENCY_CONFLICT`; simulated escrow drain failure rolls back `idempotency_records` so retrying same key after escrow replenishment succeeds (`201`).
- **Real-Backend Cross-Browser E2E:** `54/54` passed (`18` Chromium + `18` Firefox + `18` WebKit) against compiled `apps/api/dist/main.js` and production `next start` (`Next.js 15.5.29`). See [`PHASE_4_3_CROSS_BROWSER_REPORT.md`](./PHASE_4_3_CROSS_BROWSER_REPORT.md).
