## 1. Executive Summary & Purpose

This document provides a verified, source-audited inventory of all Personally Identifiable Information (PII), potentially sensitive personal data, and operational metadata processed across the CreatorConnect platform.

### Evidence Classification Standard

- **`VERIFIED_IN_SCHEMA`**: Explicitly confirmed in Prisma schema and migration DDL.
- **`VERIFIED_IN_APPLICATION`**: Explicitly implemented in TypeScript route handlers, services, or worker code.
- **`VERIFIED_IN_INFRASTRUCTURE`**: Confirmed in Docker, docker-compose, or local environment configuration.
- **`VERIFIED_BY_TEST`**: Directly verified by an automated, passing executable test suite.
- **`EXTERNAL_APPROVAL_REQUIRED`**: Relies on statutory, regulatory, or third-party legal determination.
- **`NOT_VERIFIED`**: Unconfirmed in codebase; requires operational or infrastructure inspection.

### Test Type Classification (Strict Quality Standard)

Under Phase 3B.8.2 review guidelines, **a CRUD test must NOT be presented as proof of deletion correctness**. Tests are rigorously distinguished:

- **`CRUD_ONLY_TEST`**: Tests only record creation, retrieval, or update. Does **not** test deletion or erasure.
- **`STATUS_TRANSITION_TEST`**: Tests account status mutations (`ACTIVE` <-> `SUSPENDED` <-> `DEACTIVATED`).
- **`FOREIGN_KEY_TEST`**: Tests relational constraint enforcement (`RESTRICT` / `CASCADE` / `SET NULL`).
- **`DELETION_TEST`**: Tests physical row deletion or soft-delete flag mutation.
- **`EXTERNAL_STORAGE_DELETION_TEST`**: Tests binary object deletion, version purging, and multipart abort in S3/R2 storage (`external-storage-purge.spec.ts`).
- **`END_TO_END_ERASURE_TEST`**: Tests multi-service distributed erasure orchestration (`legal-hold-concurrency.spec.ts`, `restore-sanitization.spec.ts`).
- **`NO_TESTS`**: No automated tests exist for this model.
