# CreatorConnect — Phase 5 Distributed Failure Matrix

## 1. Overview & Resilience Guarantees

In a distributed real-time platform, partial failures are inevitable. This failure matrix documents the expected behavior, automated recovery mechanisms, and data risk for all critical system failures.

---

## 2. Exhaustive Failure Matrix

| Component                | Failure Scenario                                                     | Expected System Behavior                                                                                                                                                                           | Recovery Mechanism                                                                                                                                | Data Risk                                                                           |
| :----------------------- | :------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------- |
| **PostgreSQL**           | Database becomes completely unavailable or network partitioned.      | API returns 503 Service Unavailable with RFC 7807 problem details. Socket.IO rejects message send ACKs. Outbox worker halts polling.                                                               | Managed PostgreSQL failover to standby replica (RDS Multi-AZ / Patroni). Connection pools auto-reconnect with exponential backoff.                | **ZERO DATA LOSS**. Uncommitted transactions rollback cleanly.                      |
| **Redis**                | Redis instance or cluster crashes or partitions.                     | Realtime nodes fallback to in-memory adapter (local broadcast only); rate limiter triggers `fail-closed` for sensitive mutations (503) or `bounded-fallback` for reads. Presence reflects offline. | Redis Sentinel/Cluster promotes replica. Realtime nodes reconnect and restore `@socket.io/redis-adapter` pub/sub.                                 | **ZERO BUSINESS DATA LOSS**. Ephemeral presence and cache refreshed.                |
| **Cloudflare R2 / S3**   | Object storage unavailable or API error.                             | Presigned upload requests fail with 503. Message creation without attachments continues normally. Worker retries attachment derivative jobs.                                                       | Exponential backoff retry in BullMQ worker. Clients retry upload once S3 endpoint recovers.                                                       | **ZERO DATA LOSS**. Quarantined files remain pending scan until storage restores.   |
| **ClamAV Daemon**        | Antivirus container crashes or port 3310 unreachable.                | Worker cannot verify clean status. File remains in `QUARANTINED` status. **FAILS CLOSED**: Asset is NOT promoted to `ACTIVE`.                                                                      | BullMQ worker re-queues scan job with backoff (up to 5 attempts). Docker/Kubernetes restarts ClamAV daemon container.                             | **ZERO SECURITY RISK**. No unscanned file is ever served or activated.              |
| **Socket.IO Node**       | Realtime node instance crashes or is killed by OOM.                  | Connected WebSocket clients experience TCP disconnect. Load balancer stops routing traffic to dead instance.                                                                                       | Clients execute automatic exponential backoff reconnect to surviving nodes. On connect, client executes `conversation:sync` with `sinceSequence`. | **ZERO DATA LOSS**. Reconnecting clients fetch all missed messages from PostgreSQL. |
| **Worker Process**       | Asynchronous worker process crashes mid-job.                         | In-flight BullMQ job lock expires after `lockDuration` (30s). Outbox events remain in `PROCESSING` status.                                                                                         | Surviving workers reclaim stalled jobs. Outbox supervisor reclaims orphaned `PROCESSING` events where `updated_at < NOW() - 5m`.                  | **ZERO DATA LOSS**. Jobs and outbox events executed cleanly.                        |
| **Outbox Worker**        | Dedicated outbox dispatcher crashes.                                 | PostgreSQL continues committing messages and outbox events. Realtime message fanout temporarily pauses.                                                                                            | Kubernetes / Docker restarts outbox worker container. Poller resumes draining pending events in strict creation order (`SKIP LOCKED`).            | **ZERO DATA LOSS**. Events buffered durably in PostgreSQL table.                    |
| **FCM / Push Gateway**   | Firebase Cloud Messaging returns 500/503 or network partition.       | Message creation and real-time delivery succeed completely. Push notification jobs fail and enter retry queue.                                                                                     | BullMQ retries push jobs with exponential backoff and jitter (max 5 retries). Exhausted jobs route to DLQ.                                        | **ZERO BUSINESS DATA LOSS**. Chat messages unaffected. Push retried.                |
| **Client Disconnect**    | User closes laptop, enters tunnel, or switches cell towers.          | Socket connection closes. Server marks socket disconnected. After 60s without heartbeat, Redis presence expires (`OFFLINE`).                                                                       | Client reconnects when internet restores; issues `conversation:sync` to retrieve missed messages.                                                 | **ZERO DATA LOSS**. Messages queued in database.                                    |
| **JWT Expired**          | Access token expires while client is active or sending message.      | Server rejects request with 401 Unauthorized (`AUTH_TOKEN_EXPIRED`). Socket notifies client with `auth:token_expiring`.                                                                            | Web shell uses Supabase refresh token to obtain fresh access token; reconnects or refreshes socket seamlessly.                                    | **ZERO DATA LOSS**. Mutation retried after token refresh.                           |
| **JWT Revoked**          | User logs out on another device or admin revokes session.            | API publishes `platform:user_revoked { userId }` to Redis. Realtime nodes immediately disconnect all sockets for that user.                                                                        | Sockets closed permanently until user logs in with new valid credentials.                                                                         | **ZERO DATA LOSS**. Security boundary immediately re-established.                   |
| **Duplicate Request**    | Client retries POST message send due to client-side network timeout. | Server checks unique constraint on `(sender_id, conversation_id, client_message_id)`. Catches P2002 conflict.                                                                                      | Returns existing persisted message payload with 200 OK. Sequence number is not incremented twice.                                                 | **ZERO DUPLICATION**. Exactly one logical message created.                          |
| **Duplicate Event**      | Outbox worker re-dispatches event due to network ack timeout.        | Consumer receives duplicate event. Consumer executes `INSERT INTO processed_events`.                                                                                                               | Unique constraint triggers; consumer detects duplicate and safely exits with no-op.                                                               | **ZERO SIDE-EFFECT DUPLICATION**. Consumer is strictly idempotent.                  |
| **Network Partition**    | Split-brain between API runtime and Realtime runtime.                | API commits messages to PostgreSQL and Outbox. Realtime cannot receive Redis pub/sub events.                                                                                                       | When partition heals, Outbox worker drains backlog to Redis; connected sockets receive batched updates. Clients also pull via REST sync.          | **ZERO DATA LOSS**. PostgreSQL remains the single source of truth.                  |
| **Dead-Letter Event**    | Event contains malformed data or permanent schema incompatibility.   | Event fails 5 consecutive worker dispatch attempts. Transitions to `DEAD_LETTER` status.                                                                                                           | Alert fired to on-call engineers via Sentry. Operator uses CLI tool to inspect, fix payload, and replay.                                          | **ZERO SYSTEM DOWNTIME**. Poison pill isolated from healthy queue.                  |
| **Corrupted Attachment** | Uploaded file contains truncated bytes or malformed headers.         | Worker fetches bytes; `file-type` magic bytes or Sharp parser fails to parse format.                                                                                                               | Worker marks asset `REJECTED_INVALID`; deletes object from quarantine bucket; returns error to user.                                              | **ZERO SECURITY RISK**. Corrupted file rejected before promotion.                   |
| **Invalid JWT**          | Malformed, unsigned, or forged JWT presented at handshake.           | Socket.IO handshake middleware catches verification error from `jose` / `JwtVerifier`.                                                                                                             | Connection closed immediately with 401 Unauthorized; socket never enters connected pool.                                                          | **ZERO UNAUTHORIZED ACCESS**. Handshake rejected.                                   |
| **Suspended Account**    | User account status updated to `SUSPENDED` in PostgreSQL.            | Subsequent HTTP requests fail with 403 `USER_SUSPENDED`. Active socket connections closed instantly via Redis revocation broadcast.                                                                | Access blocked until administrator resolves suspension in moderation dashboard.                                                                   | **ZERO UNAUTHORIZED ACTIVITY**. Platform protected from suspended user.             |
| **Deactivated Account**  | User account permanently deactivated / soft-deleted.                 | All authentication and authorization checks fail closed with 403 `USER_DEACTIVATED`.                                                                                                               | User data preserved in compliance with audit laws; user cannot authenticate or send messages.                                                     | **ZERO DATA LOSS**. Inactive identity locked.                                       |
